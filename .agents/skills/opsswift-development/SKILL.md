# OpsSwift 开发与维护

按用户当前需求推进 OpsSwift 源码与交付。尊重已给出的范围和授权，不为归纳技能自动增加功能、安装客户端或操作生产设备。

## 找到项目与事实

此技能随产品仓库维护。先解析 `SKILL.md` 的真实路径，取其所在目录，再向上三级定位仓库根（`<repo>/.agents/skills/opsswift-development` → `<repo>`）。从个人技能目录的符号链接调用时同样如此，不依赖固定用户名或工作区绝对路径。

1. 读取适用的 `AGENTS.md`、[开发指南](../../../docs/DEVELOPMENT.md)，核对 Git 状态及任务涉及的真实实现。
2. 版本／命令／依赖读 `package.json` 和锁文件；上游来源读 `UPSTREAM.json`；发布事实读对应 Git 标签和 Release。不要把 `main`、已发布版本和已安装程序混为同一状态。
3. 仅在涉及发行、上游接纳、资料迁移或恢复时读取 [维护规则](../../../docs/MAINTENANCE.md)。在 SECOPS 工作区遵守其唯一作业标准及事实源；技能不保存个人连接、版本表和实时进度。

## 按请求选择工作

- **功能／修复**：明确对象、入口、读写行为、失败反馈和验收结果；复用开发指南的代码地图，沿共享合同、主进程、preload、界面／CLI／MCP 的实际调用链完成改动。
- **设备／协议**：查保存的 transport 与 profile，区分查询、受限配置和自定义 RPC／PowerShell。档案、模拟协议与实机型号资格分别记录；不为完成开发自动连接用户全部设备。
- **品牌／双语**：修改人读的文案、图片和主题资源；保持英文／简体中文占位符与对比度。检查 Windows 图标及打包布局，不能只看网页截图。
- **维护／升级**：在任务分支接纳上游、依赖或迁移变更；在获准范围内完成候选制品和实际核验。只有当前任务包含发布／安装授权才执行对应动作，已有授权不重复询问。
- **知识更新**：更新产品指南或 SECOPS 权威条目，用路径和事实来源关联；普通文档修改只做相应文档检查。

## 容易破坏的兼容边界

- 1.x 的 Safe Storage 身份 `OpsMaxx`、`opsmaxx-*` 资料名、`window.opsmaxx` IPC 和 `opsmaxx` MCP 键是有意保留的接口；不得批量替换。另改身份时先设计迁移及失败恢复。
- 开发启动显式使用隔离资料目录。默认开发 userData 可触及日常资料；demo 会播种合成记录，不可指向真实目录。具体命令见开发指南。
- 现代 SSH 算法先行，按实际协商类别有限回退，主机密钥仍校验。尊重人已保存的全局／单连接策略；不能用认证错误触发算法降级。
- 真实配置沿现有权限、内容审批、加密备份和不可变计划执行；部分执行或超时不盲目重试，不把配置读回当作业务健康证明。
- OS 加密不可用时拒绝相应备份／配置；Linux 测试替身须具备实际使用的密钥库 API。不要通过放松生产加密或 TLS 让模拟测试通过。

## 验证和交接

选择能改变本次结论的检查：受影响的类型、组件、原生入口、协议模拟或真实包；完整发布门槛按维护规则执行。文档修改不强制应用全量回归或重装。

区分沙箱限制、测试替身缺项、产品失败和外部依赖失败；保留实际结果。使用真实设备、创建 Release 或切换本机客户端前核对当前授权与执行通道，测试本身不授予这些权限。

发布附件核对版本、源码、原生绑定、签名后引擎摘要、许可、CI 和远端 digest；草稿查真实 release／asset ID，不复制历史单次交付脚本的固定编号。已发布版本保持原字节，新内容使用新版本。

交付用简短中文说明实现结果、实际检查和未验证部分，并给源码／制品／证据入口。后续需求由用户决定；不要把规划写成已实现或把未完成工作标成完成。
